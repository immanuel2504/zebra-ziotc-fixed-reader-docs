Zebra IoT Connector (ZIoTC) provides four types of interfaces that enable external applications to configure and manage the reader, control RFID operations, receive tag observations, and monitor reader events.

Each interface can be configured independently with a supported endpoint, allowing the reader to communicate with local applications, enterprise systems, and cloud platforms.

## Understanding Interfaces and Endpoints

ZIoTC separates reader functions from the communication methods used to exchange information with external systems.

- **Interface:** Defines what information is exchanged with the reader.
- **Endpoint:** Defines how and where the information is exchanged.

For example, consider an application that starts RFID inventory using MQTT.

| Configuration | Description |
|---|---|
| Interface | Control |
| Endpoint type | MQTT |
| Endpoint settings | MQTT broker address, port, authentication settings, and topics. |
| Operation | Start RFID inventory. |

The Control interface determines the operation that can be performed, while the configured MQTT endpoint determines how the application communicates with the reader.

| Interface | Purpose | Communication Model | Communication Direction |
|---|---|---|---|
| Management | Configure and administer the reader. | Command and response | Application ↔ Reader |
| Control | Configure and control RFID operations. | Command and response | Application ↔ Reader |
| Data (Tag Data 1 and Tag Data 2) | Deliver RFID tag observations and supported BLE scan data. | Asynchronous data delivery | Reader → Application |
| Management Events | Deliver reader health and operational events. | Asynchronous event delivery | Reader → Application |

### Management Interface

The Management interface enables applications to configure, administer, and monitor the reader.

Typical operations include:

- Configuring network and time settings.
- Retrieving reader information, status, and configuration.
- Managing certificates.
- Updating firmware.
- Configuring heartbeat and event reporting settings.
- Configuring communication endpoints.

The application sends a management command, and the reader processes the command and returns the corresponding response.

For example, an administration application can retrieve reader information, update network settings, or configure communication endpoints without physically accessing the reader.

### Control Interface

The Control interface enables applications to control RFID operations and configure how the reader interacts with RFID tags.

Typical operations include:

- Configuring the RFID operating mode.
- Starting and stopping RFID inventory.
- Configuring tag reading behavior.
- Performing supported tag memory operations.

The application sends a control command, and the reader processes the command and returns the corresponding response.

For example, a warehouse automation application can configure the operating mode and start RFID inventory when tagged items enter the read area.

Tag observations generated during RFID inventory are delivered separately through the Data interface.

### Data Interface

The Data interface delivers RFID tag observations and, on supported readers, Bluetooth Low Energy (BLE) scan data to external applications.

Depending on the operating mode and metadata configuration, a tag observation can include information such as:

- Electronic Product Code (EPC).
- Timestamp.
- Antenna identifier.
- Received signal strength.
- Additional configured tag metadata.

ZIoTC provides two independently configurable data interfaces.

| Interface | Description |
|---|---|
| Tag Data 1 | Delivers observations through its configured endpoint. |
| Tag Data 2 | Delivers observations through a second independently configured endpoint. |

These interfaces can deliver observations to the same or different destinations using supported endpoint types.

For example, Tag Data 1 can deliver tag observations to a local inventory application using HTTP POST, while Tag Data 2 can deliver observations to a cloud analytics application using AWS IoT Core.

Unlike the Management and Control interfaces, the Data interface delivers observations asynchronously without requiring an individual request for each observation.

### Management Events Interface

The Management Events interface enables external applications to monitor reader health and operational events.

Supported events can include:

- Heartbeats containing reader health information.
- General-purpose input/output (GPIO) events.
- Warnings and errors.
- On-reader application events.

The reader delivers these events asynchronously through the configured Management Events endpoint without requiring an individual request from the application.

For example, a monitoring application can receive periodic heartbeat messages to monitor reader health and receive supported warnings or errors when they occur.

Event reporting settings, such as heartbeat intervals and supported warning thresholds, can be configured through the Management interface.

## Supported Endpoint Types

ZIoTC supports multiple endpoint types to communicate with local applications, enterprise systems, and cloud platforms.

The available endpoint types depend on the interface, reader model, and firmware version.

| Endpoint Type | Description | Typical Use Case |
|---|---|---|
| MQTT | Exchanges messages between the reader and external applications through an MQTT broker. | Reader management, RFID control, data collection, and monitoring. |
| AWS IoT Core | Enables communication between the reader and applications through AWS IoT Core. | Cloud-based reader management and data processing. |
| Azure IoT Hub | Enables communication between the reader and applications through Azure IoT Hub. | Cloud-based device integration and monitoring. |
| WebSocket | Delivers information through an established WebSocket connection. | Real-time data delivery to applications. |
| TCP/IP | Delivers data through a TCP socket connection. | Integration with local and enterprise applications. |
| HTTP POST | Sends information to a configured HTTP or HTTPS destination. | Integration with web services and application servers. |
| Keyboard Emulation (HID) | Delivers tag data as keyboard input on supported readers. | Integration with applications that accept keyboard input. |

## Interface and Endpoint Compatibility

Not all endpoint types are available for every interface. Select an endpoint based on the interface's purpose and the communication requirements of the external application.

The following table summarizes interface and endpoint compatibility.

| Endpoint Type | Management | Control | Tag Data 1 | Tag Data 2 | Management Events |
|---|---|---|---|---|---|
| MQTT | Supported | Supported | Supported | Supported | Supported |
| AWS IoT Core | Supported | Supported | Supported | Supported | To be verified |
| Azure IoT Hub | Supported | Supported | Supported | Supported | To be verified |
| WebSocket | — | — | Supported | Supported | To be verified |
| TCP/IP | — | — | Supported | Supported | To be verified |
| HTTP POST | — | — | Supported | Supported | To be verified |
| Keyboard Emulation (HID) | — | — | To be verified | To be verified | — |

:::note
Endpoint availability and simultaneous connection support may vary depending on the reader model and firmware version.
:::

In addition to configurable endpoints, applications can use the local REST API to communicate directly with the reader for supported management and control operations. For details, see the [REST API Reference](https://zebra-stage.github.io/dcs/rfid/fxr-api-docs/rest/docs/swagger.html).

For endpoint configuration procedures, see [Connect the Reader](../connect-the-reader/index.mdx).
