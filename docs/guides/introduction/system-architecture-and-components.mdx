Zebra IoT Connector (ZIoTC) runs on the reader and enables communication between the reader and external applications. It allows applications to configure the reader, control RFID operations, receive tag observations, and monitor reader events.

ZIoTC separates these functions into interfaces that can be independently configured to communicate with local applications, enterprise systems, and cloud platforms.

## System Components

The ZIoTC architecture consists of external systems, communication endpoints, reader software, reader hardware, and RFID tags.

### External Systems

| Component | Description |
|---|---|
| External applications | Local applications, enterprise systems, or cloud services that configure, control, or monitor the reader and process the data it generates. |

### Communication Endpoints

| Component | Description |
|---|---|
| Endpoints | Enable communication between ZIoTC interfaces and external systems. Supported endpoint types include MQTT, AWS IoT Core, Azure IoT Hub, WebSocket, TCP, and HTTP POST. Endpoint availability depends on the interface and reader capabilities. |

For supported endpoint types, see [Interfaces and Endpoints](./ziotc-interfaces.mdx). For endpoint configuration procedures, see [Connect the Reader](../connect-the-reader/index.mdx).

### Reader Software

| Component | Description |
|---|---|
| ZIoTC interfaces | Provide access to reader functions through four functional interfaces: Management, Control, Data (Tag Data 1 and Tag Data 2), and Management Events. |
| Reader Gateway | Connects the ZIoTC interfaces to the reader's internal management and radio functions. |
| Reader Manager | Handles reader configuration and management operations. |
| Radio Control | Controls RFID operations, such as starting and stopping tag inventory. |

For interface responsibilities and communication capabilities, see [Interfaces and Endpoints](./ziotc-interfaces.mdx).

### Reader Hardware and RFID Tags

| Component | Description |
|---|---|
| RFID radio | Performs RFID operations and communicates with RFID tags through the antenna. |
| RFID antenna | Transmits and receives radio frequency signals. Depending on the reader model, the antenna can be integrated or externally connected. |
| RFID tags | Store identification and other data that the reader can collect during RFID operations. |

## How Information Flows

The following example illustrates how commands flow from external applications to the reader and how the reader returns responses, delivers tag observations, and reports reader events during a warehouse inventory operation.

1. **Configure the reader:** An administration application sends configuration commands through the configured endpoint of the Management interface. The Reader Gateway connects the requests to the Reader Manager, which processes the commands. The corresponding responses are returned to the application through the Management interface and its configured endpoint.

2. **Start RFID inventory:** A warehouse automation application sends a start command through the configured endpoint of the Control interface. The Reader Gateway connects the request to Radio Control, which initiates RFID inventory. The reader returns the corresponding response to the application.

3. **Read RFID tags:** The RFID radio communicates with RFID tags through the antenna. Tags within the read area respond, allowing the reader to collect tag observations.

4. **Deliver tag observations:** ZIoTC sends the collected tag observations through Tag Data 1, Tag Data 2, or both, depending on the interface configuration. Each configured data interface delivers tag observations to its respective destination through its configured endpoint.

5. **Process tag observations:** The receiving applications process the tag data to update inventory records, track assets, or perform analytics.

6. **Stop RFID inventory:** When the inventory operation is complete, the warehouse automation application sends a stop command through the Control interface. Radio Control stops the inventory operation, and the reader returns the corresponding response.

Throughout reader operation, the Management Events interface independently delivers supported reader events, such as status and health notifications, to its configured destination.

The communication method and destination for each interface depend on its endpoint configuration.

## Direct Communication Using Local REST

In addition to configurable endpoints, ZIoTC provides a local REST API that allows applications to communicate directly with the reader for supported management and control operations.

For example, a provisioning application can use the local REST API to configure the reader and start RFID inventory, while the reader delivers tag observations through its configured data endpoints.

Local REST communication does not require an MQTT broker.

For supported operations, see the [REST API Reference](https://zebra-stage.github.io/dcs/rfid/fxr-api-docs/rest/docs/swagger.html).
