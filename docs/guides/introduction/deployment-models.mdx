Zebra IoT Connector (ZIoTC) can connect a reader to local applications, cloud services, or a combination of both. The deployment model depends on where the applications and services are located.

Each reader interface is configured separately and can use a different supported endpoint. The following diagram shows examples of local, cloud, and hybrid deployments.

## Local / On-Premises

In a local deployment, the reader communicates with applications or services on the local network.

**Example:** The reader sends tag observations to a local MQTT broker. A warehouse application subscribes to the tag data and uses it to track items moving through a dock door.

A local deployment can be useful when an application needs to process data at the site.

## Cloud

In a cloud deployment, the reader connects to a cloud IoT service over the network. Applications use the service to receive reader data and events or communicate with the reader.

ZIoTC can connect to cloud services such as:

- **AWS IoT Core**
- **Microsoft Azure IoT Hub**

**Example:** A retailer connects readers at multiple locations to a cloud IoT service. An inventory application receives tag observations from the readers and uses them for reporting.

The reader must have network access to the cloud endpoint and the credentials required by the selected service.

## Hybrid

In a hybrid deployment, the reader connects to both local and cloud destinations. Different interfaces can be configured for different purposes.

**Example:** **Tag Data 1** sends observations to a local application for dock-door tracking, while **Tag Data 2** sends observations to a cloud service for inventory reporting.

A hybrid deployment can support local processing and cloud-based reporting in the same solution.

Configure the reader's interfaces and endpoints to match the selected deployment. For connection instructions, see [Connect the Reader](../connect-the-reader/index.mdx).
