Zebra IoT Connector (ZIoTC) supports local, cloud, and hybrid deployments. The deployment model depends on where applications run, where reader data is processed, and how the reader communicates with external systems.

Each ZIoTC interface can be independently configured with a supported endpoint to meet the deployment requirements.

## Local (On-Premises) Deployment

In a local deployment, the reader communicates with applications and services hosted within the local network. Reader management, RFID operations, data processing, and monitoring can be performed locally.

Depending on the interface, applications can communicate with the reader using supported methods such as MQTT, HTTP POST, WebSocket, TCP/IP, or the local REST API.

**Example:** A warehouse uses RFID readers installed at dock doors to track incoming and outgoing shipments. The readers send tag observations to a local MQTT broker. A warehouse inventory application subscribes to the tag data and updates inventory records.

A local deployment is suitable when:

- Applications and infrastructure are hosted on-site.
- Tag data needs to be processed locally.
- Reader operations must not depend on internet connectivity.
- Data must remain within the organization's local network.

## Cloud Deployment

In a cloud deployment, the reader communicates with cloud-hosted applications and services through supported cloud endpoints.

ZIoTC supports integration with services such as AWS IoT Core, Microsoft Azure IoT Hub, and cloud-hosted MQTT brokers.

**Example:** A retailer deploys RFID readers across multiple warehouses. The readers send tag observations and supported reader events to a cloud IoT platform. A centralized application processes the information for inventory reporting and reader monitoring.

A cloud deployment is suitable when:

- Readers are deployed across multiple locations.
- Applications and data processing services are hosted in the cloud.
- Centralized reader management and monitoring are required.
- Data from multiple sites needs to be aggregated for reporting and analytics.

The reader must have network access to the configured cloud endpoints and the required authentication credentials or certificates.

## Hybrid Deployment

In a hybrid deployment, the reader communicates with both local and cloud-based applications. Different ZIoTC interfaces can use different supported endpoints based on application requirements.

**Example:** A warehouse uses a local application for dock-door tracking and a cloud application for centralized inventory reporting.

The reader can be configured as follows:

| Interface | Example Endpoint | Purpose |
| --- | --- | --- |
| Management | AWS IoT Core | Remote reader administration. |
| Control | MQTT (local broker) | Local control of RFID operations. |
| Tag Data 1 | HTTP POST | Deliver tag observations to a local inventory application. |
| Tag Data 2 | Azure IoT Hub | Deliver tag observations to a cloud analytics application. |
| Management Events | MQTT (cloud-hosted broker) | Centralized reader monitoring. |

A hybrid deployment is suitable when:

- Some operations must be performed locally.
- Cloud services are required for centralized monitoring or analytics.
- Multiple applications require reader data.
- Local processing and cloud-based reporting are required within the same solution.

## Choosing a Deployment Model

| Consideration | Local | Cloud | Hybrid |
| --- | --- | --- | --- |
| Application location | On-premises | Cloud | On-premises and cloud |
| Data processing | Local | Cloud | Local and cloud |
| Network requirements | Local network | Connectivity to cloud endpoints | Local network and connectivity to cloud endpoints |
| Typical use case | On-site inventory tracking | Centralized multi-site inventory management | Local automation and centralized reporting |

Select a deployment model based on application requirements, network availability, data processing requirements, and infrastructure.

For supported interfaces and endpoint types, see [Interfaces and Endpoints](./ziotc-interfaces.mdx).
