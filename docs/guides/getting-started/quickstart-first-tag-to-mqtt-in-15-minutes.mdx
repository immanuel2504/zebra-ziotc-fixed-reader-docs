In this quickstart, you configure the reader's **Control** and **Tag Data 1** interfaces to use MQTT, start RFID inventory, and receive a tag observation in an MQTT client.

:::note
Configure, preview, and publish each interface separately, even when both interfaces use the same broker.
:::

## Before You Begin

- Complete the reader installation, sign in to the web console, set the regulatory region, and [verify readiness](./verify-reader-readiness-and-status.mdx).
- Have a compatible RFID test tag and a configured antenna in the read area.
- Have access to an MQTT broker and a client that can publish and subscribe. The reader and client must be able to reach the broker.
- Obtain the broker's connection details, credentials, and certificates if required. Choose topics and permissions for the Control and Tag Data interfaces.

## Step 1: Configure the Control Interface

1. In the reader web console, open **Settings > Endpoint** and select **Control**.
2. Set **Endpoint Type** to **MQTT** and enter the broker connection details.
3. On the **Topic** tab, configure the Control command and response topics.
4. Configure certificates if required, select **Preview** to review the settings, and select **Publish**.
5. Confirm that the Control interface shows **connected**.

For field descriptions and screenshots, see [Connect to an MQTT Broker](../connect-the-reader/connect-to-an-mqtt-broker.mdx).

## Step 2: Configure the Tag Data Interface

1. Select **Tag Data 1** and set **Endpoint Type** to **MQTT**.
2. Enter the broker connection details and configure the Tag Data topic on the **Topic** tab.
3. Configure certificates and batching and retention as needed.
4. Select **Preview**, review the settings for **Tag Data 1**, and select **Publish**.
5. Confirm that the Tag Data 1 interface shows **connected**.

Use a different MQTT client ID for each active connection to the same broker.

## Step 3: Subscribe to the Topics

Connect your MQTT client to the broker used by each interface. If Control and Tag Data use different brokers, create a separate connection to each broker. Subscribe to the Control response topic and the Tag Data topic **before** sending the start command. Use the topic names configured for your deployment.

| Topic | Example |
| --- | --- |
| Control command | `readers/reader-01/control/command` |
| Control response | `readers/reader-01/control/response` |
| Tag Data | `readers/reader-01/data/tags1` |

### Optional: Check the Reader Version

If you also configured the **Management** interface for MQTT, you can verify it by requesting version information. Connect to its broker and subscribe to the configured Management response topic first. For example, publish to `readers/reader-01/management/command` and receive the response on `readers/reader-01/management/response`.

**Request:**

```json
{
  "command": "get_version",
  "command_id": "req-version-01",
  "payload": {}
}
```

**Example response:**

```json
{
  "command": "get_version",
  "command_id": "req-version-01",
  "response": "success",
  "payload": {
    "readerApplication": "2.0.7-5",
    "radioFirmware": "2.1.57.0"
  }
}
```

The example response is shortened. Version values and other fields depend on the reader. See the [`get_version` reference](https://zebra-stage.github.io/dcs/rfid/fxr-api-docs/mqtt/docs/#op-get_version). You can continue without this optional Management check.

## Step 4: Start Inventory and Read a Tag

### Configure the Operating Mode

Publish the following `set_mode` request to the **Control command topic**. This example selects `SIMPLE` mode, uses antenna 1, and requests the antenna number in tag reports. Use the antenna port or beam appropriate for your reader and installation. This command changes the reader's operating mode settings.

**Request:**

```json
{
  "command": "set_mode",
  "command_id": "req-set-mode-01",
  "payload": {
    "type": "SIMPLE",
    "antennas": [1],
    "tagMetaData": ["ANTENNA"]
  }
}
```

**Example response on the Control response topic:**

```json
{
  "command": "set_mode",
  "command_id": "req-set-mode-01",
  "response": "success",
  "payload": {}
}
```

To check the configured mode, publish `get_mode` to the **Control command topic**:

```json
{
  "command": "get_mode",
  "command_id": "req-get-mode-01",
  "payload": {}
}
```

**Example response on the Control response topic:**

```json
{
  "command": "get_mode",
  "command_id": "req-get-mode-01",
  "response": "success",
  "payload": {
    "type": "SIMPLE",
    "antennas": [1],
    "tagMetaData": ["ANTENNA"]
  }
}
```

The actual response can include additional settings. Confirm that the mode and antenna configuration are suitable before starting inventory. See the MQTT [`set_mode`](https://zebra-stage.github.io/dcs/rfid/fxr-api-docs/mqtt/docs/#op-set_mode) and [`get_mode`](https://zebra-stage.github.io/dcs/rfid/fxr-api-docs/mqtt/docs/#op-get_mode) references.

### Start Inventory

1. In your MQTT client, publish the following message to the **Control command topic**:

   ```json
   {
     "command": "start",
     "command_id": "req-start-01",
     "payload": {
       "doNotPersistState": true
     }
   }
   ```

2. Check the Control response topic for the matching `command_id`. An example successful response is:

   ```json
   {
     "command": "start",
     "command_id": "req-start-01",
     "response": "success",
     "payload": {}
   }
   ```

### Receive Tag Data

Present the test tag to the antenna and check the subscribed **Tag Data topic**. An example observation is:

```json
{
  "type": "SIMPLE",
  "timestamp": "2019-08-24T14:15:22Z",
  "data": {
    "antenna": 1,
    "eventNum": 1,
    "format": "epc",
    "idHex": "3005fb63ac1f3681ec880468"
  }
}
```

The tag identifier (`idHex`), timestamp, and other fields vary by tag and reader configuration.

See the MQTT [`start`](https://zebra-stage.github.io/dcs/rfid/fxr-api-docs/mqtt/docs/#op-start) command and [tag data events](https://zebra-stage.github.io/dcs/rfid/fxr-api-docs/mqtt/docs/#op-tagDataEvents) reference. Use a new `command_id` for each command.

## Step 5: Stop Inventory

Publish the following message to the same **Control command topic**:

```json
{
  "command": "stop",
  "command_id": "req-stop-01",
  "payload": {}
}
```

Check the Control response topic for the matching `command_id`. For example:

```json
{
  "command": "stop",
  "command_id": "req-stop-01",
  "response": "success",
  "payload": {}
}
```

After inventory stops, confirm that new tag observations stop arriving. If a response is `failure`, check its payload for error details.

See the MQTT [`stop`](https://zebra-stage.github.io/dcs/rfid/fxr-api-docs/mqtt/docs/#op-stop) command reference.

If no tag observation arrives, check the antenna and operating mode, confirm both interfaces are connected, and verify that the MQTT client is subscribed to the configured Tag Data topic.
